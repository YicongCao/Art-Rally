# Art Rally 开发计划

版本：v0.1 / 2026-10-13

## 1. 目标、现状与已确认决策

交付目标：一个可以重复试玩的桌面拉力游戏垂直切片，包含一辆原创四驱车、砂石/泥地/柏油与积水体验、一条约 3 km 的夕阳山林赛段、基础计时与路书，以及手柄和键盘操控。

当前已完成 Godot 4.7.2 标准版、GDScript、Jolt、120 Hz 固定物理步与物理插值的环境配置。已有环境验证场景和自动冒烟测试；尚无车辆、轮胎模型、测试场或正式赛道。开发和首轮性能验收以当前 Apple M4 Pro Mac 为基准，使用 Forward+ / Metal。

已确认的产品决策：

- 手柄是驾驶质感的主要标定设备，键盘也是首版必须可玩的输入方式，不作为最后补丁。
- 键盘通过渐进输入、回正、车速相关转向限制和油门/制动平滑降低操作难度；两类设备使用相同车辆、轮胎与路面参数。
- 默认自动换挡、自动离合；支持手动序列换挡。首版不实现 ABS、牵引力控制、主动稳定系统或自动反打，不用额外抓地、偏航力或横向速度修正掩盖模型问题。
- 一车一赛段，固定夕阳天气，程序化低多边形资产；不依赖建模 MCP。
- 首版不做联网、生涯、精细车损、动态车辙、轮胎温度磨损或方向盘力反馈，不承诺浏览器版本。
- 按验收门槛推进，不预设交付日期；物理阶段未通过时，不用增加美术内容替代修复。

## 2. 系统设计与开发接口

### 2.1 输入与键盘易用性

所有输入先进入同一层适配，再向物理层提供 `DriverCommand`：归一化转向 [-1, 1]、油门/制动/手刹 [0, 1]、换挡请求。重置、暂停和镜头切换是会话操作，不混入轮胎模型。模拟每个固定步读取一份命令；换挡等离散事件只能消费一次。

手柄保留渐进输入，提供可调死区、响应曲线与轻度转向速率限制。扳机分别控制油门和制动；初期沿用现有映射，检测实际连接设备，不把实现绑定到固定设备编号。

键盘采用独立的 `InputProfile`，默认启用辅助：

- A/D 生成目标转向，不在一帧内从零跳到满舵；按住持续增加，松开渐进回正，同时按下左右键时目标为零。
- 车速越高，持续按键的目标转角和同向打方向速度越保守；低速保留足够转角完成发夹和倒车。
- 反向按键采用较快的过零响应，不能让平滑导致无法及时反打；高速限制平滑恢复，不能突然剪掉已有转角。
- W/S 分别渐进建立油门和制动力，制动响应比油门更快；手刹不做长时间缓入。S 始终是制动，倒挡通过挡位操作选择，不在减速过程中突然变成倒车。
- 初始配置采用约 0.3 秒油门建立、0.12 秒制动建立、0.2–0.3 秒低速满舵建立；这些仅是调校起点，必须与物理固定步无关地按时间计算。
- M1 提供标准/轻辅助两档键盘输入配置；M5 在设置界面暴露转向灵敏度、回正速度和踏板平滑。默认标准辅助，不增加车辆力学特权。

失焦和手柄断开时清除输入并暂停，恢复时需要明确继续；切换设备不遗留油门、刹车或方向状态。菜单按键不触发车辆操作。

### 2.2 车辆物理

使用 `RigidBody3D` 车身 + 四轮接触查询 + 自定义悬架/轮胎/传动，不使用 `VehicleBody3D` 作为最终驾驶模型。车身轴向约定为 -Z 前进、+Y 向上，世界单位为米、千克、秒。

- **车身：** 第一辆车以约 1,250 kg、230 kW、2.6 m 轴距、1.6 m 轮距为初始参数；质量、重心、惯量、轮径和轮端安装点独立配置，不从外观网格猜测。
- **悬架：** M1 使用四轮射线、弹簧、压缩/回弹阻尼和渐进限位，M2 加前后防倾杆。以静态载荷和设计静态压缩量推导起始刚度，避免凭外观调弹簧。
- **轮胎：** 使用连续的参数化纵横向力曲线，包含峰值、峰后滑动段、载荷敏感性、组合滑移摩擦椭圆和松弛响应。采用低速正则化及受抓地上限约束的低速接触解，避免停车时抖动和抱死穿零。
- **动力：** M1 接入受限轮端驱动/制动转矩验证闭环；M2 替换为发动机转矩曲线、转速惯性、自动离合、六个前进挡/N/R、发动机制动、换挡中断和有限锁止能力的限滑差速器。中央初始 50:50 分配，手刹作用后轮并近似中央解耦。
- **积分：** 接触和刚体保持 120 Hz；轮速、轮胎力与动力总成采用 4 个内部子步，平均接触力作用于车身。明确这不是 480 Hz 的完整碰撞求解。使用物理积分回调施力，不在渲染帧改变速度。
- **受力：** 由车轮接触位置和力自然产生侧倾、俯仰和偏航，不重复叠加载荷转移；保留底盘碰撞，但不让车轮碰撞摩擦与自定义轮胎力重复作用。空气阻力和滚阻必须消耗而非注入能量。

每轮离地后清除路面力，保持轮速与传动响应；重新接触时不沿用失效接触点。刚体重置只在物理同步点执行，同时清除轮速、输入滤波、轮胎松弛状态和镜头/物理插值历史。

M3 在射线版本上实现可切换的轮胎包络多点采样，用于验证减速带、沟坎和落地；不把采样点数量乘到总支撑力上。首版不增加多刚体轮架或完整非簧载质量，保留这一建模限制并使用适合该接触模型的障碍尺度。

### 2.3 参数、路面与遥测

新增类型化 Godot Resource 配置：`VehicleConfig`、`TireConfig`、`SurfaceProfile`、`InputProfile`、`StageDefinition`。配置与运行状态分离；调参不得污染共享资源中的车辆实时状态。

- `WheelContact` 提供接触位置、法线、悬架长度和表面采样；悬架输出非负轮荷，轮胎模型接收轮荷/滑移/表面并输出纵横向力，传动模型处理轮端转矩和轮速。
- `SurfaceSample` 表达基础材质与水深。基础材质包含柏油、砂石、泥地及路外草土；水洼是有边界和深度的覆盖区域，不是第四种互斥地面。
- 同一查询结果驱动物理、轮胎音和粒子；材质不从渲染像素颜色反推。边界只在接触范围内混合，左、右轮可得到不同材质。
- 水层增加经验湿态抓地修正与迎水阻力；水阻作用在实际入水轮处。首版不宣称精确水滑或流体模拟。
- 物理每步采集 `VehicleTelemetry`，HUD 降频至约 20 Hz；记录四轮载荷、悬架行程、滑移、侧偏、轮速、力、路面、水深及车身状态。
- 输入和遥测写入有界内存缓冲，试跑结束后导出 CSV 与配置/引擎版本信息到 `user://telemetry/`；不在每个物理步进行同步磁盘写入。

数据流固定为：输入命令 → 接触与材质 → 悬架/轮胎/传动 → 刚体受力 → 遥测与表现。声音、粒子和镜头只读取状态，不能反向控制车辆物理。

各阶段结束时都提交可运行场景、测试结果、参数基线和已知限制；从 M1 开始每阶段均可手动试玩。实现期间同步更新 README，不在一次交付里堆完所有阶段。

### M1 的实施顺序

1. 建立测试场：平直加速/制动区域、半径 25 m 定圆、低速蛇形、缓坡、单个减速带。全部使用基础网格，视觉与碰撞共用尺寸。
2. 建立参数资源、输入命令和键盘/手柄适配；先用独立测试验证归一化、时间响应与离散按键，不需要车辆才能测输入。
3. 建立车身、四轮接触和悬架静态平衡；先不加动力，验证四轮总载荷和车身静止。
4. 接入轮速、驱动/制动转矩和基础组合轮胎力；加入低速停车约束，禁止使用直接设定车速来达到可驾驶效果。
5. 接入跟车镜头、HUD、接触/力向量调试绘制及重置；加入自动测试输入源，确保自动测试与玩家驱动同一车辆接口。
6. 完成键盘初调、设备切换/断开处理和回归测试后，将默认运行入口切到测试场；保留原环境验证场景。

M1 里的临时传动也必须基于轮端转矩；它只缺少发动机和差速器细节，不另造一套街机车辆控制器。M2 替换模型时保持 `DriverCommand` 与遥测接口稳定。

### M4–M5 的内容实现约束

首条赛段为“夕照松岭”，采用人工路线控制点与固定种子装饰，路宽通常 4.5–6 m。以砂石为主，依次穿插林间泥地/积水、柏油发夹、上坡砂石和一个有预告的坡顶跳跃。用涵洞处理低洼排水，首版不另做桥梁系统。

采用 `Curve3D` 的弧长采样生成道路、路肩和附近地形，碰撞与视觉共用几何源。路面噪声必须受坡度和连续性限制，轮胎可感知的起伏进入碰撞几何。网格按路段分块，首版在发车前全部准备好碰撞，只对装饰做距离裁剪，暂不引入运行时碰撞流式加载。

检查点按路线顺序并校验行进方向；重置到最近的已通过安全恢复点并加 5 秒罚时，完整重跑清空成绩。路书以路线进度和车速提前量触发，倒车不重复播报；文字 UI 首版使用中文。

树木和观众用实例化低多边形组合，山体以远景层次表现，天空使用渐变与简单云层。观众放在有可见边界的安全退距区域，不制作撞人玩法。跟车、引擎盖、简化驾驶舱共享同一插值后的车辆状态；驾驶舱震动可关闭。

音效先用程序合成或明确允许使用的占位素材，覆盖转速/负载、滑移、砂石、泥水和触底，不把占位音效作为正式录音品质承诺。首版只提供少量悬架/制动平衡调校，默认值可恢复，不扩展为完整车库系统。

## 4. 测试与验收

扩展现有 `scripts/dev.sh check` 执行导入检查、原环境冒烟测试、纯模型测试和车辆场景测试；任一脚本/资源错误都返回非零。复用 Godot 原生 headless 测试入口，不新增测试框架依赖。长时间赛段和 GPU 性能测试单独运行，不混进每次快速检查。

| 测试层 | 场景与验收标准 |
| --- | --- |
| 输入 | 同一键盘时间序列在不同渲染帧率下得到同样的物理步命令；所有模拟值合法；换挡只触发一次；反向输入可及时过零；失焦/断开不留油门 |
| 纯模型 | 无接触时轮胎力为零；左右输入对称；组合力不越过抓地上限；正常载荷区间内极限力随载荷增加但单位载荷抓地下降；制动/滚阻/水阻不制造能量；低速无 NaN/Inf |
| 静态与低速 | 平面静态稳定后平均总轮荷与 mg 偏差不超过 5%；平地停车 10 秒漂移小于 0.1 m；缓慢起步/停车/倒车不出现周期性抖动 |
| 柏油动态 | 对称车辆直线加速不产生持续单向偏航；80 km/h 制动、25 m 定圆、转向阶跃和蛇形有记录；弯中占用纵向抓地会降低可用横向力 |
| 悬架与落地 | 单轮越坎、连续起伏、坡顶离地、落地、翻车重置均无数值爆炸；离地轮无地面力，落地后行程和阻尼恢复；重置无插值拖影和残留转矩 |
| 多路面 | 对所选首版参数和相同制动协议记录柏油/砂石/泥地距离；不用通用“真实路面排序”替代标定；单侧入水有对应方向的阻力偏航、双侧对称入水无持续单侧偏航 |
| 回归与帧率 | 同一机器/引擎/参数、按物理步回放相同输入；30/60/120 FPS 下比较直线加速和停车距离，偏差目标低于 1%；不要求混沌赛段长回放逐帧一致或跨平台确定性 |
| 赛段与操控 | 道路无自交、断面翻转、碰撞裂缝、出生点阻塞；重复生成布局一致；键盘与实际手柄均完成整段，记录失控点、恢复次数和可读性问题 |
| 性能与发布 | M4 Pro 上 1080p、预热后完整赛段测试，目标 P95 帧耗时不超过 16.7 ms、车辆计算 P95 不超过 2 ms/步；记录 P99 与卡顿位置，区分模型耗时和 Jolt 总物理耗时 |

数值标准是工程验收起点，不是真实赛车认证。首次建立动态基线后保存结果，之后每次改核心参数都比较停车距离、定圆响应和悬架曲线；不能仅以“更容易漂移”判断更拟真。

手柄型号目前未指定。实现使用 Godot 标准映射；真实扳机量程、按键与热插拔仍需要实际设备试玩，不能用合成输入测试冒充硬件验收。未接入设备时明确标记这一项未验收，不阻塞键盘和物理开发。

## 5. 交付纪律与后续边界

- 优先级固定为稳定接触与低速行为 → 轮胎/动力/姿态 → 多路面 → 赛段 → 表现 → 性能打包；测试工具随功能一起交付，不延后到最后。
- 既有环境场景、开发脚本和策划案继续保留；本计划确认技术栈与实施顺序，若初稿中的“引擎候选”等内容冲突，以本计划为准。
- 每阶段报告实际完成、自动验证、需要人工验证的项目和模型限制。没有实测数据时，只声称内部一致性与驾驶趋势通过验证。
- 首版以本机 macOS 可运行包为交付；对外分发所需签名、公证、Windows 适配与在线更新另列后续工作。
- 下一次实现从 M1 开始，不直接制作完整 3 km 美术赛道，也不一次性承诺达到商业拉力模拟器的驾驶精度。
