# Art Rally：拟真驾驶、风格化画面的拉力游戏策划案

版本：v0.1 / 2026-10-13

实施补充：技术栈已确定为 Godot 4.7.2 + GDScript + Jolt，手柄优先且必须支持更易操作的键盘输入。阶段交付和验收详见 [开发计划](DEVELOPMENT_PLAN.zh-CN.md)；本文保留最初策划背景。

定位：以《DiRT Rally 2.0》的驾驶体验作为方向参考，制作原创车辆、赛道与美术，不复制其素材、品牌授权内容或专有实现。

本文中的车辆数值、路面参数与赛道长度均为初始设计目标，需要通过原型测试调整，不是已验证的物理数据。

## 1. 项目愿景

做一个“看起来简洁，开起来有重量”的拉力驾驶游戏。

玩家应当能感受到轮胎接近抓地极限的过程、不同路面的制动距离、车身侧倾和俯仰、悬架压缩与回弹，以及路面起伏对车辆姿态的影响。画面不追求照片级真实，而是用低多边形模型、准确的道路轮廓、清晰的色彩和夕阳氛围，让玩家把注意力放在驾驶上。

### 核心体验原则

1. **物理先于内容。** 先把一辆车、一组测试弯和四类路面做对，再扩充车辆和赛段。
2. **拟真不等于难以控制。** 车辆响应必须有可解释的因果，失控前应有转向、声音、姿态或震动反馈。
3. **滑动不是脚本。** 漂移来自轮胎、驱动、转向和重心运动，不通过自动横移、假偏航力或预设漂移状态实现。
4. **道路一眼可读。** 主路、路肩和不可安全通行的区域明确区分，不用隐藏碰撞墙维持路线。
5. **每一项拟真都有验证方法。** 用遥测、测试场和对比试驾验证，而不是只靠“感觉像”。

## 2. 第一版范围

### 垂直切片应包含

| 模块 | 第一版目标 |
| --- | --- |
| 车辆 | 1 辆虚构四驱拉力赛车，支持重置与基础调校 |
| 赛道 | 1 条约 3 km 的原创山地林间混合路面赛段 |

| 驾驶 | 油门、制动、转向、换挡、手刹，手柄优先 |
| 模式 | 自由试车、计时赛段、重跑 |

| 场景 | 主路、路肩、树林、山体、天空云层、夕阳、少量观众 |

### 第一版不做

- 多人联网、开放世界、复杂生涯、车辆购买与经济系统。
- 大量授权车型、精细内饰、车辆软体变形或完整部件损坏。
- 动态泥地车辙、土壤有限元、逐花纹轮胎、水体流体仿真。
- 昼夜循环、动态天气、多赛季植被与高精度观众行为。
- 一开始就支持方向盘力反馈；但输入和车辆反馈接口要预留。

第一版固定为夕阳、干燥天气，局部泥地和积水由赛道设计解释，例如林间排水不良、低洼处与涉水点。

## 3. 驾驶物理设计

### 3.1 总体模型

推荐结构：**真实尺度的车身刚体 + 四轮接触与悬架模型 + 自定义轮胎力 + 简化动力总成**。

场景统一使用米、千克、秒。车身重心、惯量、轮距、轴距和碰撞形状必须独立可调。车身可见模型只是表现层，不反过来决定物理参数。

每个物理更新的基本流程：

1. 查询四个车轮的接触点、法线、路面材质与水深。
2. 计算悬架行程、压缩速度、弹簧阻尼力及接触载荷。
3. 计算轮端局部速度、纵向滑移率和侧偏角。
4. 根据载荷、路面、滑移与轮胎状态计算纵向力和横向力。
5. 更新发动机、离合器、变速箱、差速器、轮速与制动力矩。
6. 将接触力施加到实际作用点，由刚体求解车身平移和旋转。
7. 更新遥测，插值车辆画面，驱动声音和特效。

上述流程是逻辑分层，不意味着动力总成与轮胎必须各自只更新一次；强耦合的轮速和轮胎力需要在同一子步内计算。

初始目标为固定 120 Hz 物理更新，渲染独立运行。根据稳定性和性能测试，对轮胎与动力总成使用 2–4 个子步；如果只有轮速积分被细分，不能把它当作车身和接触系统也达到相同频率。第一阶段就测试不同帧率下结果是否一致。

### 3.2 轮胎：最重要的开发投入

第一版使用可调、可解释的刷子模型或参数化力曲线，不追求一开始就套用参数来源不明的完整 Pacejka 模型。

必须具备：

- **纵向滑移。** 驱动空转和制动抱死分别影响驱动力与制动力。
- **侧偏角。** 轮胎横向力随侧偏逐渐建立，经过峰值后进入滑动区。
- **组合滑移。** 制动或加速占用抓地能力，弯中不能同时获得满额纵向和横向力。
- **载荷敏感性。** 载荷增加时可用抓地增加，但不能简单按固定摩擦系数无限线性增长。
- **过渡响应。** 通过松弛长度或等价的一阶响应模型表现轮胎力建立过程，避免抓地瞬间开关。
- **低速稳定。** 滑移率在接近零车速时需要连续正则化，停车与缓慢起步不能抖动或产生无穷大。
- **离地处理。** 无接触载荷时不产生路面抓地，车轮仍受传动和制动转矩影响。

组合滑移以摩擦椭圆等方法限制合力，但最终曲线需要按路面调校。砂石与泥地不只改变一个摩擦系数，还要改变峰值位置、滑动区、滚阻和纵横向响应。

砂石允许较大的滑移工作区，让车辆有可控的滑动；柏油轮胎响应更直接、极限更集中；泥地更容易空转且速度损失更明显。松散路面的轮胎推土效应可以用经验阻力近似，但不能宣称是完整土壤模拟。

温度、磨损、胎压暂不进入第一版核心求解，只保留参数扩展接口。轮胎调校优先于车型数量。

### 3.3 悬架

每轮支持：弹簧刚度、预载或静态支撑设置、压缩阻尼、回弹阻尼、总行程、限位缓冲、车轮质量和视觉轮径。

前后轴分别设置防倾杆；左右轮行程差产生耦合作用，使侧倾刚度和轮荷分配可以调校。悬架力必须在正确位置施加，不能只把整个车身向上推。

建议分两级实现：

- **原型级：** 单车身刚体 + 四轮射线悬架，快速验证轮胎和载荷反馈。
- **垂直切片级：** 评估车轮扫掠接触或多点接触采样，改善沟坎、跳跃落地和小障碍物表现；只在测试证明有必要时引入非簧载质量或多刚体轮架模型。

射线悬架不是完整悬架仿真，容易漏掉轮胎侧面碰撞，也不能自然表达轮跳。接触升级应由测试驱动，不能仅靠增加采样数就认定已经拟真。

### 3.4 底盘与车身动态

- 由重心高度、轴距、轮距和惯量决定侧倾、俯仰及偏航响应。
- 加速时车头抬起、制动时点头，弯中车身侧倾，起伏路面产生连续姿态变化。
- 载荷转移来自接触力、重心和刚体运动；如采用简化修正，必须避免与现有求解重复计算。
- 空中姿态由已有角动量、轮端反作用和有限空气阻力决定，不增加不明来源的自动扶正力。
- 着地后依据压缩速度和悬架行程处理冲击，触底通过渐进限位响应，避免无限弹簧力。
- 底盘、护板和车身保留简化碰撞，不能让轮胎抓地模型替代所有车体接触。

第一版不追求复杂车架柔性和悬架几何全部自由度，但要在行程、质量、阻尼和作用位置上自洽。

### 3.5 动力总成

起始车型为虚构的现代紧凑型四驱拉力赛车，约 1,250 kg、约 230 kW，六挡序列式变速箱。这些只是初始标定目标。

模拟发动机转矩曲线、转速惯性、限转、发动机制动、简化离合器、挡位传动比、终传比、前后轮端转矩分配和轮速。

差速器分阶段实现：先提供稳定的前后轴转矩分配，再加入基于轮速差和锁止能力的限滑响应。不能长期依靠“各轮固定分配相同转矩”代替完整四驱行为，也不能无限转移转矩解决单轮失去接触的问题。

手刹主要作用于后轮；四驱传动耦合如何处理需要车型逻辑明确，避免一拉手刹就不合理地锁死所有车轮。第一版可近似模拟手刹触发的中央传动解耦。

### 3.6 操控与辅助

- 手柄为主：可调死区、转向曲线、速度相关的最大输入速率与输入平滑。
- 键盘使用渐进转向和可调回正，作为可玩性兼容，而非主要物理调校标准。
- 自动换挡和自动离合可开启；ABS、牵引力控制和稳定辅助分别配置，默认不启用会改变拉力驾驶核心体验的强辅助。
- 所有辅助都必须可关闭；调校物理时使用同一套输入滤波，避免靠辅助掩盖问题。
- 方向盘力反馈放到后续阶段，届时需要回正力矩、接触冲击和路面反馈模型，不能直接把手柄震动数据当作方向盘力矩。

## 4. 路面材质与交互

技术上采用“基础路面 + 水层”的结构：砂石、泥地、柏油为基础材质；水洼是有范围和深度的覆盖层，因此可以有湿砂石和湿柏油。

| 路面 | 驾驶特征 | 需要调整的物理量 | 画面与声音 |
| --- | --- | --- | --- |
| 砂石 | 可控滑移、入弯较松、制动距离较长 | 滑移曲线、峰值与滑动抓地、滚阻、经验松散材料阻力 | 暖灰或浅褐路面、扬尘、碎石声 |
| 泥地 | 抓地不稳定、空转明显、行驶阻力较大 | 纵横向曲线、附加阻力、区域含水状态 | 深褐色、泥点、湿润反光、低沉轮胎声 |
| 柏油 | 响应直接、制动效率高、越过极限后仍需可预测 | 峰值抓地、滑动抓地、侧向刚度、滚阻 | 炭灰色、较少颗粒、清晰胎噪 |
| 水洼 | 抓地降低、迎水阻力、左右轮不同步入水产生偏航 | 水深、接触速度、湿态抓地、轮端附加阻力 | 水面、局部反射、飞溅与涉水声 |

水洼不是一个固定“低摩擦地板”：浅水以湿态抓地和轻微阻力为主，较深积水增加水阻。高速水滑只作基于速度、水深和轮胎状态的经验近似，第一版不模拟真实胎纹排水，也不承诺精确预测水滑阈值。

路面交界处按轮胎接触范围做有限宽度混合，防止材质标签切换造成力突变，但不要把明确的柏油与砂石边界抹成没有差异的宽渐变。

非主路区域同样有物理材质，例如草地、松土和石块。驶离道路后应当因为低抓地、起伏或障碍而危险，不是因为所有草地都不可进入。

## 5. 首条赛道设计

### 5.1 主题与节奏

临时名称：**夕照松岭 / Sunset Ridge**。

约 3 km、单向点到点、道路大部分宽约 4.5–6 m，局部扩宽至约 7 m。以山地砂石林道为主体，包含一个柏油连接段、林间泥地和低洼积水。总爬升下降控制在可读、可驾驶的尺度，而不是随机堆出夸张坡度。

初步里程分段如下，具体弯道数量在灰盒试驾后确定：

| 里程 | 内容 | 体验目的 |
| --- | --- | --- |
| 0–400 m | 起点、宽砂石直道、缓弯 | 熟悉油门、制动与基础抓地 |
| 400–1,150 m | 林间中高速砂石连续弯、轻微起伏 | 建立节奏，感受横向载荷与滑移 |
| 1,150–1,650 m | 泥地慢弯、低洼水洼、窄桥或涵洞 | 体验低抓地、左右轮不同路面与风险管理 |
| 1,650–2,100 m | 柏油连接路、重刹车点、发夹弯 | 强烈但可预判的路面变化 |
| 2,100–3,000 m | 上坡砂石、一个可读的坡顶跳跃、终点弯 | 综合检验悬架与姿态控制 |

首次试玩目标约 3–5 分钟完赛，不把极限速度作为唯一评价标准。路面变化前应有视觉预告和基础路书提示，不在盲弯后突然放置无法回避的深水障碍。

### 5.2 生成方法

第一条赛道采用**约束式生成 + 人工校验**，不采用完全随机生成。

1. 人工定义路线控制点、关键弯、路面区段、跳跃位置和安全缓冲区。
2. 用样条生成中心线，再生成主路、路肩和两侧地形。
3. 根据曲率、坡度和连续性约束限制道路几何，检查发夹、坡顶和拼接处。
4. 以固定随机种子布置树木、草丛、石块与观众，保证布局可重复。
5. 自动检测自交、道路断裂、过陡边坡、障碍侵入道路与不安全出生点。
6. 人工完整试驾，修正路书、刹车空间、视距与落地区域。

基础起伏与轮胎能够感知的沟坎需要实际进入碰撞几何；只靠法线贴图不能让悬架运动。碰撞网格可低于视觉细节，但不能低到抹平关键路面特征。

### 5.3 路书

第一版提供关键弯前的文字或图标提示：弯向、弯急缓、发夹、收窄、坡顶和水洼。提示距离随车速调整，并结合路线距离判断，不用简单固定时间播放。

完整语音领航员可后续加入。关键坡顶、跳跃落地和路面切换应当先有明确提示，避免把视野限制误当作拟真难度。

## 6. 场景与美术

### 6.1 视觉方向

采用低多边形、柔和大色块、暖夕阳与冷远山。道路细节精简，但轮廓、坡度、宽度和材质变化必须清楚。

| 元素 | 建模方案 | 可读性要求 |
| --- | --- | --- |
| 主路 | 样条道路网格，按区段切换材质 | 砂石浅灰褐、泥地深褐、柏油炭灰，不同粗糙度辅助辨认 |
| 路肩 | 独立边带与自然过渡 | 比主路更暗或更偏土色，体现边缘、排水沟与高差 |
| 非行驶区域 | 草地、乱石、陡坡、树根 | 橄榄绿与赭色为主，用地形和障碍表达风险 |
| 树木 | 少量树干、树冠组合，实例化与 LOD | 稀密变化，不遮挡重要刹车点或路面变化 |
| 远山 | 低面数层叠山体、雾化颜色 | 冷蓝灰、降低对比，远离主路颜色 |
| 天空 | 固定夕阳方向、天空渐变、云层贴图或简单云片 | 不做复杂体积云，不让夕阳眩光吞掉路面 |
| 车辆 | 简化车壳、独立车轮、明显姿态 | 保留轴距、轮距、悬架动作与轮胎转速 |
| 观众 | 胶囊或方块身体、球形头、简单配色 | 无面部细节，少量招手动作，位置有安全退距 |

不要仅凭色相区分主路和危险区域：边缘轮廓、明暗、地形和标识共同承担提示，兼顾色觉差异与夕阳阴影。

### 6.2 观众与安全

只在起终点、发夹外侧的安全高地和少量观赛点聚集。观众区域用彩带、护栏或天然地形分隔，不把人群放在正常冲出路线正前方。

第一版不做撞人玩法、不加入血腥反馈、不把人物作为可弹飞的刚体障碍。异常进入观众保护区域时使用提示、计时惩罚与安全重置；保护范围必须可见，不能影响正常道路驾驶。

### 6.3 性能分层

树木和观众优先使用实例化；远山不参与详细碰撞；近处树干、岩石和护栏保留简化碰撞。扬尘与泥水限制粒子数量。道路分块加载或裁剪，但物理接触区域必须提前准备，防止高速行驶时出现碰撞缺口。

## 7. 声音、镜头与驾驶反馈

- 引擎声随转速和负载变化，包含收油和发动机制动反馈。
- 各轮胎根据路面、滑移与接触载荷混合声音，不只用车速驱动统一胎噪。
- 砂石声、甩泥声、入水声和悬架触底声具有区别。
- 跟车镜头保留延迟与阻尼，但不把镜头摆动当作车身运动；驾驶舱震动限制幅度，并提供关闭选项。
- 手柄震动表达路面粗糙度、冲击和轮胎失去抓地，避免持续最大震动。
- 夕阳、尘土与水花服务于速度感，不应长期遮挡前方主路。

HUD 只保留速度、挡位、转速、赛段时间、下一条路书和重置提示。开发遥测是独立开关，不与正式 HUD 混在一起。

## 8. 技术路线与模块

### 8.1 平台与引擎

第一阶段建议以桌面本地运行作为主目标，优先保证物理调试与稳定帧率，不先承诺浏览器版。

引擎暂定候选：

- **Godot 4 + 支持 Jolt 的稳定版本：** 轻量、开放，适合快速迭代原创低多边形赛道；车辆核心需自定义，不把内置车辆节点直接当作拟真成品。
- **Unity LTS + PhysX：** C# 工具与商业工作流较成熟；同样使用自定义轮胎和车辆逻辑，而不是仅调整默认轮碰撞组件。

建议在开发启动前做一个小型接触与性能验证，再锁定引擎。若项目坚持 Web 发布，需要单独测试部署兼容、物理预算、输入支持和加载时间，不应默认桌面方案无成本迁移。

### 8.2 模块边界

```text
InputController        输入、死区、滤波、辅助配置
VehicleBody            质量、惯量、重心、碰撞与受力
WheelContact           接触查询、法线、材质和水深
SuspensionModel        弹簧、阻尼、限位、防倾杆
TireModel              滑移、侧偏、载荷敏感性、组合抓地
DrivetrainModel        发动机、离合器、变速箱、差速器、轮速
SurfaceDatabase        基础路面与水层参数
TrackGenerator         路线、地形、道路网格、碰撞和种子
StageSession           起终点、计时、检查点、重置与路书
VehiclePresentation    车轮/车身显示、粒子、声音、镜头
TelemetryRecorder      数据采样、曲线、输入回放、测试结果
```

车辆参数、轮胎参数、路面参数和赛道布局独立保存为配置资源。不能把调校数值散落在输入、声音和表现脚本里。

固定种子意味着场景布局可复现，不保证跨平台刚体求解逐帧确定。第一版输入回放用于同一环境回归测试；若后续开发鬼影，可直接记录车辆轨迹，而不是假定相同输入永远得到相同位置。

## 9. 开发阶段与验收门槛

按“验收通过再进入下一阶段”组织开发。未确认人力、引擎和目标硬件之前，不把日期作为承诺。

| 阶段 | 交付物 | 进入下一阶段的门槛 |
| --- | --- | --- |
| A：车辆灰盒 | 平地、圆环、坡道、减速带，一辆方块车 | 起步、停车、转向、跳跃无持续抖动或数值爆炸；帧率变化不改变基础响应 |
| B：轮胎与底盘 | 轮胎曲线、组合滑移、悬架、四驱传动、遥测 | 稳态圆周、刹车、转向阶跃与减速带测试通过；能解释推头、甩尾与触底原因 |
| C：多路面 | 四类体验、局部混合接触、湿态和水阻 | 用相同输入和初始状态重复测试，路面差异稳定；材质边界不产生非物理弹飞 |
| D：完整赛段灰盒 | 约 3 km 赛段、生成约束、计时、路书与重置 | 可完整跑通，无断路、碰撞缺口和无法恢复的卡车位置；风险点有预告 |
| E：风格化场景 | 树、山、云、夕阳、观众、声音与特效 | 场景可读；主路始终可辨；特效不遮蔽必要驾驶信息 |
| F：标定与试玩 | 参数基线、性能报告、玩家反馈 | 同环境可重复测试；至少包含拉力游戏玩家与普通手柄玩家的反馈，修正明显不可解释响应 |

B、C 阶段完成前，不投入大规模车辆建模与赛道装饰。若轮胎或接触模型尚不稳定，应暂停内容扩展。

## 10. 测试场与可量化指标

### 10.1 必备测试

| 测试 | 观察与记录 |
| --- | --- |
| 静止与低速爬行 | 轮速、低速滑移、悬架静态压缩、是否自发移动 |
| 直线加速与收油 | 轮端转矩、空转、换挡中断、发动机制动、俯仰 |
| 固定初速制动 | 停车距离、抱死、左右轮制动力、车身稳定性 |
| 稳态圆周 | 横向加速度、转角、侧偏、四轮载荷和抓地饱和顺序 |
| 转向阶跃 / 蛇形 | 偏航响应、侧倾、轮胎力延迟与恢复过程 |
| 单侧低抓地制动 | 左右差异导致的偏航，不能自动保持直线掩盖问题 |
| 减速带与连续起伏 | 行程、阻尼、触底、回弹、接触丢失 |
| 坡顶与落地 | 离地状态、空中轮速、接触恢复、落地峰值 |
| 单侧入水 | 速度损失、水深响应和左右轮阻力导致的偏航 |
| 不同渲染帧率 | 相同固定步与输入条件下的运行结果变化 |

基础遥测包括：车速、加速度、偏航角速度、侧倾/俯仰、每轮滑移率与侧偏角、轮速、接触载荷、纵横向力、悬架行程、路面 ID、水深、发动机转速、挡位和物理耗时。

每次修改核心模型先跑固定测试，再跑赛段。没有车辆实测数据时只能验证内部一致性、可信趋势与主观驾驶反馈，不能宣称已经复刻真实赛车或《DiRT Rally 2.0》的精确动力学。

### 10.2 性能目标

- 最终目标为约定参考硬件上 1080p、60 FPS 的稳定体验，而不是未指定设备上的性能保证。
- 单车物理预算先以约 2 ms / 120 Hz 步作为观测目标，随后根据选定平台调整。
- 优先消除物理尖峰、临时内存分配和碰撞加载卡顿，平均 FPS 不能代替稳定性指标。
- 固定步求解、渲染插值和输入采样需要一起验证，避免画面流畅但操控延迟或车辆抖动。

## 11. 主要风险与控制

| 风险 | 控制方式 |
| --- | --- |
| 轮胎很滑，却不像真实驾驶 | 同时检查峰后曲线、载荷、转向输入和传动，不只改摩擦系数 |
| 射线车辆在沟坎和落地时异常 | 早建障碍测试场，逐步升级接触，必要时再增加非簧载模型 |
| 四驱模型过于简化 | 分阶段加入限滑与传动耦合，测试单轮离地和手刹 |
| 视觉起伏与物理起伏不一致 | 道路视觉和碰撞共用生成数据，对关键路段做接触 QA |
| 随机生成的赛道不好开 | 生成受约束，保留人工控制点，完整试驾后才发布 |
| 调校数量暴增、问题无法定位 | 固定基线车与基线路面，一次只改变一类参数，记录版本与遥测 |
| 美术和粒子遮挡驾驶信息 | 在驾驶视角检查对比、视距与特效浓度，而非只看截图 |
| 目标不断扩大 | 第一版只承诺一车一段，后续功能必须建立在验收通过的物理核心上 |

## 12. 后续扩展顺序

1. 更完整的领航员语音、录制轨迹的鬼影与赛段成绩。
2. 悬架、差速器、制动平衡和齿比的有限调校界面。
3. 前驱与后驱车型，用同一物理核心验证不同驾驶特征。
4. 新赛段、雨天、更多轮胎组合，以及经验证的湿态模型。
5. 方向盘力反馈、较完整的悬架几何、温度与磨损。
6. 最后再评估损伤、动态车辙、联网和生涯内容。

## 13. 下一步建议

下一步不是先制作完整漂亮的赛道，而是制作一个**驾驶物理验证原型**：一辆灰盒四驱车、柏油/砂石/泥地测试区、一个有水深变化的水洼、圆环与减速带、可随时打开的四轮遥测面板。

这个原型应先回答三个问题：

1. 轮胎极限是否渐进、可预测，弯中加减速是否影响转向能力？
2. 车辆是否通过真实受力产生俯仰、侧倾、离地和落地反馈？
3. 相同车辆进入不同路面时，是否自然产生区别，而不是靠脚本切换驾驶模式？

只有这三个问题得到可靠答案，再把它放进“夕照松岭”的完整风格化赛段。
