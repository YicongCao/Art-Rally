# 自动驾驶与虚拟输入

自动驾驶是 M6 的生产功能，也是完整跑段、性能长跑和独立应用演示的统一驾驶器。它默认关闭，不修改车辆物理，也不直接设置位置或速度。

## 使用

- **F10**：关闭 → 虚拟键盘 → 虚拟手柄 → 关闭。
- 暂停菜单中的“自动驾驶”下拉框提供相同选择。
- C 仍可切换跟车、引擎盖和驾驶舱视角；F9 可观察四轮、动力和自动驾驶目标。
- 任意真人转向、油门、制动、手刹或换挡输入会立即关闭自动驾驶并接管车辆。
- 暂停、恢复和重跑会清理规划器与输入历史，但保留本次选择；重新启动应用时始终恢复为关闭。

HUD 中的 `AUTO · KB` / `AUTO · PAD` 表示当前输入模式，下一行显示目标速度和相对路线中心的横向误差。

## 算法

`RallyRoutePilot` 使用赛段中心线而不是摄像机图像：

1. 将车辆位置投影到 `RallyStageRoute`，维护局部搜索索引。
2. 按车速在前方 5–13 m 选择预瞄点，使用轴距和目标夹角求期望转向。
3. 采样前方曲率生成弯道速度上限，并对泥地、积水和坡顶进一步限速。
4. 用目标速度与实际速度的误差生成油门和制动意图。

驾驶器只产生输入意图。虚拟键盘把意图量化为二值按键，再经过键盘转向、回正、高速限幅和踏板平滑；虚拟手柄产生连续摇杆/扳机值，再经过同一手柄死区、响应曲线和输入滤波。两者最终与真人输入共用 `DriverCommand → 车辆物理` 链路。

自动驾驶不会注册假手柄、注入操作系统事件、触发虚拟设备震动，也不会在卡住时传送车辆。自动测试遇到长时间没有路线进度会失败并保留诊断结果。

## 自动验收

```bash
./scripts/dev.sh stage-check --layout=AWD --input=vgamepad
./scripts/dev.sh stage-check --layout=AWD --input=vkeyboard
./scripts/dev.sh stage-matrix
./scripts/dev.sh autopilot-render-check
```

`stage-matrix` 串行运行 FWD / AWD / RWD × 虚拟键盘 / 虚拟手柄六种组合。每组必须依次通过全部 31 个检查点、恢复 0 次、持续取得路线进度且最大横向偏离不超过道路门槛。输出位于忽略版本控制的 `logs/`。

虚拟手柄只能验证游戏内部的摇杆死区、响应曲线、踏板链路和车辆结果，不能验证具体物理手柄的系统映射、真实扳机量程、震动或断开重连。M6 仍保留真实设备人工验收。

## 成绩与遥测

会话和遥测区分：

- `human_keyboard`
- `human_gamepad`
- `autopilot_vkeyboard`
- `autopilot_vgamepad`
- `mixed_takeover`
- `test_harness`

只要一次计时跑段曾启用自动驾驶，即使后来由真人接管，也不会进入人类最佳成绩。完整自动驾驶结果作为独立参考记录。
